# 합격 기준 상세 (Rubric)

모든 항목은 PASS/FAIL. FAIL에는 반드시 근거를 적는다. 근거 없는 판정은 무효.

|---|---|---|
| S1 출처 | PASS/FAIL | |

| S3 상태 확인 | PASS/FAIL | |
| S4 조건 준수 | PASS/FAIL | |

| D1 스키마 | PASS/FAIL | validate_db.py 출력 첨부 |

FAIL 아래에 `무엇이 부족한가 / 무엇을 바꿔야 하는가`. 해당 경로의 항목만 판정한다(서치면 S, 업데이트면 D).

## 공고 서치 (S)

**S1 출처**
- 공고마다 URL, 출처 유형(공식/플랫폼/기타), 확인일이 있다
- 공식 페이지가 있으면 그것이 대표 URL이다

**S2 중복 없음**
- URL이 같거나 회사+직무+근무지가 같으면 같은 공고로 본다
- 기존 항목은 새로 만들지 않고 갱신(상태, 마감일, 메모)

**S3 상태 확인**
- 원문을 열어 확인했다. 열리지 않으면 `확인 불가`
- 마감일이 원문에 없으면 "미기재", 추정 금지

**S4 조건 준수**
- 제외 조건(지역, 직무, 산업, 고용 형태, 기업 규모 등)을 어긴 후보가 없다
- 조건을 임의로 넓히지 않았다

**S5 적합도 근거**
- 필수 요건마다 근거 등급이 있다
- 근거 등급에는 DB 항목 ID가 있다 (공백은 ID 없음 가능)

## 이력 DB (D)

**D1 스키마**
- `python3 -I scripts/validate_db.py career-db/experiences.md` 가 오류 0건으로 끝난다

**D2 출처**
- 항목마다 `출처`가 있고 값은 `사용자 진술` 또는 문서명
- `원문` 필드가 사용자의 말을 보존한다

**D3 지표 4요소**
- 값, 단위, 기간, 귀속이 있다. 비율이면 분모도
- 하나라도 모르면 `상태: 미검증`이며 확정 상태가 아니다

**D4 충돌 처리**
- 같은 지표의 값이 바뀌면 사용자 확인 후 변경, `changelog.md`에 사유 기록
- 조용히 덮어쓰지 않았다

**D5 폐기 보존**
- 폐기는 `상태: 폐기`. 항목 삭제 없음
- 폐기 값이 다른 항목이나 분석에 다시 쓰이지 않았다

**D6 diff 제시**
- 변경 전/후를 보여주고 승인을 받은 뒤 파일을 바꿨다

**D7 민감 정보**
- 퇴사 사유, 휴직 사유, 건강, 연봉, 동료 개인 사정, 회사에 대한 불만이 없다
- validate_db.py의 민감어 경고를 확인했다

## 종료 조건

- 해당 경로 항목 전부 PASS → 확정
- FAIL → 해당 부분만 수정, 재검증. **최대 3회**
- 3회 후에도 FAIL → "확인 대기"로 표시하고 막힌 항목과 질문을 적어 전달

## 적합도 판정

| 판정 | 의미 |
|---|---|
| 강한 적합 | 필수 요건 대부분이 직접 증거(DB ID)로 뒷받침 |
| 보강 필요 | 핵심 요건 일부가 전이 경험 또는 미확인 |
| 중대한 불일치 | 필수 경험·자격이 실제로 없음 |

이 판정은 편집 판단이며 합격 확률이 아니다. 퍼센트를 만들지 않는다.
