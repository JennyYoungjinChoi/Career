# 인계 파일 양식

역할끼리는 대화가 아니라 파일로 주고받는다. 세션이 끊겨도 이어갈 수 있게 한다.

## `work/candidates.md` (Scout 출력)

```markdown
# 서치 후보 — YYYY-MM-DD

조건: <search-criteria 요약>

| # | 회사 | 직무 | 근무지 | 상태 | 마감 | 출처 유형 | URL | 확인일 | 중복 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | | | | 모집 중 | 미기재 | 공식 | | | 신규 |

제외 K건: <사유별 건수>
확인 불가 N건: <사유>
```

## `work/db-diff.md` (Archivist 출력)

```markdown
# DB 변경안 — YYYY-MM-DD

## 신규 EXP-012
(전체 항목)

## 수정 EXP-004
- 지표: 전환율 12% → 14%
  사유: 사용자 정정 (YYYY-MM-DD)
  기존 값은 changelog에 보존

## 폐기 EXP-007
- 사유: 사용자 철회
- 상태: 확정 → 폐기 (삭제하지 않음)

## 확인 필요
- ...

승인 대기
```

## `work/review.md` (Auditor 출력)

```markdown
# 검증 — <경로> — 회차 N/3

| 기준 | 판정 | 근거 |
|---|---|---|
| ... | PASS/FAIL | |

## 수정 필요 (FAIL만, 개선 사항 먼저)
1. 무엇이 부족한가:
   무엇을 바꿔야 하는가:

STATUS: PASS | FAIL | 확인 대기
```

## `changelog.md` 한 줄 양식

```
YYYY-MM-DD | EXP-004 | 지표 수정 | 12% → 14% | 사용자 정정
YYYY-MM-DD | EXP-007 | 폐기 | 확정 → 폐기 | 사용자 철회
YYYY-MM-DD | EXP-012 | 신규 | - | 사용자 진술
```

## `확인 필요` 양식

```
확인 필요: <무엇이 불확실한가, 한 줄>
- 해석 A: <내용> → DB에 미치는 영향
- 해석 B: <내용> → DB에 미치는 영향
(답 전까지: <미검증으로 기록 / 해당 항목 보류>)
```

## 채팅 반환 양식

**서치**
```
신규 N건 / 갱신 M건 / 제외 K건(사유)
우선 볼 공고 3건: <회사 직무 — 한 줄 근거(DB ID)>
확인 불가: <있으면>
검증: S1~S5 PASS
```

**분석**
```
판정: <강한 적합 / 보강 필요 / 중대한 불일치> — <한 줄 근거>
핵심 공백(최대 3): <유형, 요건, 필요한 보강>
JD 저장: <위치>
```

**업데이트**
```
신규 N / 수정 M / 폐기 K — changelog 반영
validate_db.py: 오류 0, 경고 W
확인 대기: <있으면>
```
