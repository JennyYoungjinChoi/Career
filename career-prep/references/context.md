# 맥락 참고 (Context)

> 날짜가 있는 참고 맥락이다. 영구적으로 검증된 사실 목록으로 취급하지 않는다.
> `< >` 칸은 사용자가 본인 상황으로 채운다. 제출용 템플릿이라 값은 비워 두었다.

## 1. 저장 위치 원칙

| 데이터 | 파일 | 공개 저장소 |
|---|---|---|
| 이력 DB | `career-db/experiences.md` | **올리지 않음** |
| 변경 이력 | `career-db/changelog.md` | **올리지 않음** |
| 검색 조건 | `career-db/search-criteria.md` | 올리지 않음 |
| 공고 트래커 | `career-db/postings.csv` | 올리지 않음 |
| 템플릿, 가상 예시 | `templates/`, `examples/` | 올려도 됨 |

실제 데이터는 개인 드라이브나 로컬 폴더에 둔다. 기존 폴더를 먼저 검색하고 재사용한다. ID를 추측하거나 폴더를 중복 생성하지 않는다.

## 2. 검색 조건 (search-criteria.md에 기록)

- 직무군: `<>`
- 연차 범위: `<>`
- 지역, 근무 형태: `<>`
- 선호 산업: `<>`
- **제외 조건**: `<>`
- 우선순위 가중: `<예: 직무 일치 > 산업 > 규모>`
- 서치 주기, 한 번에 볼 건수: `<>`

조건은 사용자가 바꾸기 전까지 유지한다. 서치 중 조건을 임의로 넓히지 않는다.

## 3. 이력 DB 구조

DB 항목의 단위는 "한 프로젝트 안의 한 성과"다. 같은 프로젝트의 항목은 `프로젝트` 필드로 묶는다. 같은 고객·같은 시기라는 사실은 사용자가 말했을 때만 적는다.

필수 필드는 `templates/experience-db.md` 참고. 핵심은 다음이다.

- `원문`: 사용자가 말한 그대로
- `정리`: 읽기 쉽게 다듬은 문장 (원문의 의미를 넘지 않는다)
- `역할`: led / managed / built / operated / contributed / supported
- `지표`: 값 / 단위 / 기간 / 귀속 / 분모
- `상태`: 확정 / 미검증 / 폐기
- `최종확인일`, `출처`

## 4. 상태 규칙

| 상태 | 의미 | 분석에서의 사용 |
|---|---|---|
| 확정 | 사용자가 확인한 값 | 사용 가능 |
| 미검증 | 값, 단위, 기간, 귀속 중 빠진 것이 있음 | 사용하되 "미검증" 표시 |
| 폐기 | 사용자가 정정·철회함 | **사용 금지.** 삭제하지 않고 이력으로 보존 |

## 5. 자주 쓰는 정정 규칙

- 최신 사용자 정정이 항상 오래된 값보다 우선한다.
- 정정은 DB 항목에 반영하고 `changelog.md`에 한 줄 남긴다. 이 파일에는 규칙만 둔다.
- 폐기된 값은 어떤 분석에서도 다시 꺼내지 않는다.

## 6. 공고 트래커 상태값

`후보` → `검토` → `지원 예정` → `지원 완료` / `보류` / `제외` / `마감`

- 상태 변경은 사용자가 말한 것만 반영한다. 지원 여부를 추정하지 않는다.
- `지원 완료`는 사용자가 "지원했다"고 말했을 때만 기록한다.
