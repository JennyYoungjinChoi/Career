# 역할별 지침 (Role)

SKILL.md 역할표를 실제로 수행할 때의 세부 지침. 해당 단계에서만 읽는다.

## Scout — 공고 탐색자

- 검색 조건은 `search-criteria.md`가 기준이다. 조건에 없는 직무로 넓히지 않는다.
- 같은 공고가 여러 플랫폼에 있으면 공식 채용 페이지를 대표 URL로 삼고 나머지는 메모로 남긴다.
- 원문을 직접 열어 확인한다. 검색 결과 스니펫만으로 요건을 적지 않는다.
- 상태는 `모집 중 / 마감 / 확인 불가` 중 하나. 마감일이 없으면 "미기재".
- 제외 조건에 걸린 공고는 후보에 넣지 않고 "제외 K건(사유)"로만 보고한다.
- 적합도 판단은 하지 않는다. 넘길 때는 원문 사실만 적는다.

## Archivist — DB 기록자

- 입력은 사용자의 진술이다. **원문 필드**에 그대로 옮기고, 정리된 문장은 **정리 필드**에 따로 둔다.
- 사용자가 말하지 않은 것을 채우지 않는다. 비어 있으면 `미확인`으로 두고 좁게 묻는다.
- 역할 동사는 사용자가 쓴 의미 그대로: led(주도) / managed(관리) / built(구축) / operated(운영) / contributed(기여) / supported(지원).
- 지표는 값, 단위, 기간, 귀속, 분모를 함께. 하나라도 모르면 `미검증`.
- 같은 프로젝트를 이어서 기록하는지, 별도 프로젝트인지 사용자가 말하지 않았으면 단정하지 않는다.
- 변경은 diff로만 제안한다. 승인 전에는 쓰지 않는다.

## Analyst — 대조 분석가

- 근거 등급: 직접 증거 / 전이 경험 / 미확인 / 공백.
- 항상 DB 항목 ID를 인용한다. ID 없는 근거는 근거가 아니다.
- 전이 경험을 입증된 소유권으로 바꿔 쓰지 않는다.
- JD가 말한 것과 해석을 분리한다. 예: "글로벌 보고 라인" 여부는 JD 문장으로만 판단한다.
- 핵심 공백은 최대 3개. 유형(표현 / 증거 / 경험·자격)을 표시한다.
- 증거 공백은 경로 D의 질문으로 넘긴다. 없는 근거를 만들어 메우지 않는다.

## Auditor — 검증자

- 판정은 PASS/FAIL, 근거는 재현 가능하게 구체적으로.
- 직접 고치지 않는다. 무엇이 부족한지와 무엇을 바꿔야 하는지만 적는다. 점수보다 개선 사항을 먼저 쓴다.
- 합격 기준을 바꾸지 않는다.
- 스키마 검사는 `scripts/validate_db.py`를 실제로 실행한 결과로 판단한다. 읽어보고 통과라고 하지 않는다.
- 3회 재검증 후에도 FAIL이면 "확인 대기"와 구체적 질문을 남긴다.
